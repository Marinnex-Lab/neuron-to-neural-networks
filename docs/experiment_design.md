# Experiment design

Every experiment in this repository is written down before it is run. A design states the question, the variables, the controls, and the decision rule. The results are then generated by a script, so they can be reproduced.

## Template

1. **Question.** One sentence, ending with a question mark.
2. **Hypothesis.** What you expect, and in which direction.
3. **Independent variable.** The one thing that changes.
4. **Controls.** Everything else that stays fixed: data, architecture, steps, initialization scheme, optimizer.
5. **Confounders.** Things that change together with the independent variable and could explain the result. Name them and either control them or state the limitation.
6. **Repetitions.** Random seeds, and how many.
7. **Metrics.** Held-out metrics for decisions. Training metrics only as a convergence check.
8. **Decision rule.** What result counts as support, and how the chosen setting is picked.
9. **Scope.** Which data, architecture and budget the result applies to.

## Example: learning rate on a non-linear task

Implemented in `experiments/learning_rate_study/run.py`.

| Element | Choice |
|---|---|
| Question | How does the learning rate affect validation loss of a 2 → 4 → 1 network? |
| Hypothesis | Very small rates do not converge within the step budget. Very large rates may oscillate. An intermediate rate gives the best validation loss. |
| Independent variable | learning rate in {0.05, 0.2, 0.5, 2.0, 8.0} |
| Controls | data generated with a fixed seed, 1500 full-batch steps, uniform initialization scheme, the same architecture |
| Confounder | The number of steps is fixed, so a slow rate is penalized for speed as well as final quality. The report states this. |
| Repetitions | initialization seeds 0 to 4 |
| Metrics | validation loss (decision), validation accuracy, training loss (convergence check), count of diverged runs |
| Decision rule | lowest mean validation loss among settings with no diverged run |
| Scope | this dataset, this architecture, this budget |

## Example: multilayer XOR success rate

Implemented in `experiments/multilayer_network/run.py`.

| Element | Choice |
|---|---|
| Question | How often does gradient descent solve XOR with 2, 3 or 4 hidden units? |
| Independent variable | hidden width |
| Controls | learning rate 0.5, 3000 steps, data, initialization scheme |
| Repetitions | seeds 0 to 19 |
| Metric | accuracy 100% (success) and final loss |
| Scope | XOR only. Success rates for other tasks are not implied. |

## Common mistakes

- Choosing hyperparameters with the test set or the training loss.
- Changing two things at once, such as an activation and its initialization.
- Reporting one seed as a result.
- Forgetting divergence: a run with a non-finite loss must be counted, not dropped.
- Reporting a result that the script does not produce.
